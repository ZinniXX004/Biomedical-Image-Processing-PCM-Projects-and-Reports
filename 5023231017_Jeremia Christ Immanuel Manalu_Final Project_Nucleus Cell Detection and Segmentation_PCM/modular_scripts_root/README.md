# Nucleus Cell Detection and Segmentation (PCM)

This repository contains code and scripts for nucleus cell detection and segmentation used in the final project for the PCM course. The project is laid out to be run from a Python virtual environment and supports installing dependencies from `requirements.txt` or via PEP-517 tooling through `pyproject.toml`.

## Requirements

- Python 3.13+ (3.14 recommended)
- `pip` and optionally `venv` or `virtualenv`
- (Optional) `poetry` if you prefer to manage dependencies via `pyproject.toml`

## Setup — quick steps (Windows PowerShell)

1. Create a virtual environment named `.venv` in the project root:

```powershell

python -m venv .venv

.\\.venv\\Scripts\\Activate.ps1

python -m pip install --upgrade pip
```

2. Install dependencies (choose one):

- From `requirements.txt` (simple, reproducible):

```powershell

pip install -r requirements.txt
```

- Using `pyproject.toml` (if you use Poetry or another PEP-517/518 tool):

With Poetry:

```powershell

pip install poetry

poetry install
```

Or, using pip's editable install for local packaging (installs the project package):

```powershell

pip install -e .
```

3. Create a `.env` file (optional but recommended for local configuration).

&#x20;  Example `.env` contents:

```

\# .env

FLASK\_ENV=development

SECRET\_KEY=super-secret-key
```

Note: Do NOT commit secrets to version control. Add `.env` to `.gitignore` if necessary.

## Running the project

- Run the main program:

```powershell

python main.py
```

- For other utilities or background workers, see `worker.py`.

## Files you should know

- `pyproject.toml` — project metadata and build-system configuration. Used by PEP-517 tools and by Poetry if you choose it.
- `requirements.txt` — a plain list of packages to install via `pip`.
- `.venv/` — recommended virtual environment folder (not checked in)
- `.env` — local environment variables (not checked in)
- `main.py` — project entry point
- `worker.py` — worker/utility script used by the project
- `main.spec` and `build/` — artifacts created by PyInstaller (if you build a bundled executable)

## Notes and recommendations

- Prefer keeping your virtual environment in `.venv` so editors detect it automatically.
- Use `requirements.txt` for reproducible `pip` installs and CI; use `pyproject.toml` / `poetry` when you want modern dependency management and lockfiles.
- Keep secrets out of the repository; use `.env` for local testing and a proper secret store for production.
- If packaging with PyInstaller, `main.spec` and `build/` will be created — treat these as build artifacts.

## Troubleshooting

- If imports fail, confirm the virtual environment is activated and that packages were installed into it.
- If a package is missing, run `pip install -r requirements.txt` or `poetry install` depending on your chosen workflow.
